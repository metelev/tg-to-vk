# Telegram → VK

Отдельный сервис: новые посты Telegram-канала публикуются на стене сообщества VK. Поддерживаются текст, одна или несколько фотографий, видео и сочетания этих вложений в альбоме. Текст из подписи становится текстом записи VK. Бот читает только `channel_post` одного заданного канала.

## Что понадобится

- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather), добавленный **администратором** в исходный канал. Включите право читать сообщения канала. Этот бот должен быть отдельным от бота для VK → Telegram: у Telegram Bot API один поток `getUpdates` на токен.
- ID канала, например `-100…`. Бот получает его в поле `chat.id` после тестовой публикации. Его можно посмотреть временным запросом `getUpdates` с новым токеном на своём компьютере; не пересылайте результат целиком, в нём может быть содержимое поста.
- Числовой ID сообщества VK (положительное число).
- **Пользовательский VK-токен администратора** сообщества с правами `wall`, `photos`, `video`. Для загрузки фото на стену и видео официальный API требует именно пользовательский токен. Храните его только в `.env` на сервере. Получение токена зависит от зарегистрированного VK-приложения; при настройке проверьте разрешения и срок действия в настройках приложения.
- Если VK отклоняет `wall.post` с пользовательским ключом, укажите `VK_GROUP_TOKEN` — ключ доступа этого же сообщества с правом публикации на стене. Загрузка медиа продолжит использовать `VK_USER_TOKEN`.
- Если Telegram недоступен с сервера напрямую, понадобится HTTP- или SOCKS-прокси для запросов к Telegram. VK вызывается напрямую.

## Настройка на Ubuntu

Скопируйте этот проект в `/opt/projects/tg-to-vk`, затем выполните от `root`:

```bash
cd /opt/projects/tg-to-vk
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

Заполните `.env` в редакторе. Если для Telegram нужен прокси, укажите его адрес в `TELEGRAM_PROXY_URL`; иначе оставьте поле пустым. Проверьте настройки без отправки поста:

```bash
.venv/bin/python -m tg_to_vk check
.venv/bin/python -m unittest discover -s tests -v
```

Далее создайте отдельного системного пользователя и службу:

```bash
useradd --system --home /opt/projects/tg-to-vk --shell /usr/sbin/nologin tg-to-vk
mkdir -p data
chown -R tg-to-vk:tg-to-vk data
chown root:tg-to-vk .env
chmod 640 .env
cp deploy/tg-to-vk.service /etc/systemd/system/tg-to-vk.service
systemctl daemon-reload
systemctl enable --now tg-to-vk.service
systemctl status tg-to-vk.service --no-pager
```

Журнал: `journalctl -u tg-to-vk.service -n 50 --no-pager`. После запуска опубликуйте **новый** пробный пост в Telegram-канале и проверьте его в VK. Бот не читает историю канала, но обработает обновления, накопившиеся с момента его добавления.

## Надёжность и ограничения

- Долгий опрос Telegram (`getUpdates`, 15 секунд) не требует публичного адреса и HTTPS для входящих запросов.
- Обновления и очередь сохраняются в SQLite до подтверждения получения. После сбоя сервис продолжит обработку. `guid` у `wall.post` остаётся неизменным для одного поста и защищает от дубля при повторной отправке.
- Альбом собирается 5 секунд после последнего полученного элемента. Очень поздний элемент альбома может не попасть в запись; при таком сбое его потребуется обработать вручную.
- Telegram Bot API позволяет скачать файл до **20 МБ** через `getFile`. Более крупное видео сервис помечает ошибкой без повторных попыток. Другие типы вложений (опросы, документы, стикеры) не публикуются.
- Ошибки сети и API повторяются через минуту и записываются в журнал. Если токен или права неверны, исправьте `.env` и перезапустите службу. Файл `.env`, база и скачанные медиа не входят в репозиторий.
